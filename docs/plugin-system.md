# Phosdeck 插件系统方案

首批交付是插件机制和三个随 App 提供的小工具。每种接入口都由一个内置插件实际使用。当前产品的扩展点限随包插件。开放第三方插件前，需要用另一团队签名并公证的独立包核对安装、系统批准和工作连接。

| 接入口 | 首批内置插件 | 用户得到什么 |
|---|---|---|
| 图像处理（观片预览） | **软打样** | 选择打印机与纸张的 ICC 配置，在画布比较送印前与模拟印刷的颜色，可叠加目标色域警告 |
| 提出原生编辑 | **选取高光** | 当前照片多一个可调范围、可用画笔修边的蒙版 |
| 实时显影效果 | **暖调印相** | 当前照片多一个可随时重调强度的效果，预览和导出都包含它 |

**一次调用怎样工作。** 用户打开工具，Phosdeck 冻结选中的照片版本并启动插件。拖动参数时，宿主请求预览。观片工具只把结果交给画布，关闭即恢复普通显示；编辑工具由用户确认后提交原生编辑或可重算效果。插件独立运行，保存的作品和历史由 Phosdeck 管理。下面三个工具是这份设计的实际调用方；开发接口、生命周期和故障恢复见[实现方案](#实现方案与平台依据)。

## 三个内置插件

### 软打样：在屏幕上检查这张照片送印后的颜色

用户在编辑工作区开启“软打样”，选择与打印机、墨水及纸张匹配的 ICC 输出配置，切换普通视图与打样视图。例如，拍舞台时鲜红的灯光在选定纸张上可能变暗；打开“色域警告”可以看出哪些颜色超出该印刷条件能表现的范围。用户可以在打样时继续调照片，常规编辑照常进入历史，开关打样、换纸和显示警告属于窗口的观片状态。关闭后恢复普通显示；普通导出始终使用自身设置。新开窗口默认普通显示，可在本机记住上次选的配置。[Apple“预览”的软打样工作流](https://support.apple.com/guide/preview/prvw41540291/mac)

**为什么选它。** 它能验证一个真正独立的图像处理插件能否拿到有明确色彩含义的成片，使用用户选定的资源做计算，并只接管屏幕上的照片。首批图像处理入口返回“观片预览”；以后有单张降噪或多帧合成需求时，再为此入口增加“保存派生照片”。首批三个内置插件各占一种接入口，软打样可复用发现、握手、计算和取消协议。

**首版打样条件。** 先模拟“当前 Phosdeck 的 SDR sRGB 成片按所选输出 ICC 送印”。宿主按目标裁区和输出尺寸完成显影、暖调、局部编辑与颗粒，在白色承印底上以线性光合成透明区域，按现有 sRGB TIFF16 输出规则得到一份不透明的送印源。普通对照与打样预览从这份送印源分出。首版支持相对色度与感知两种印刷意图，相对色度模式开启黑点补偿，感知模式按配置文件的感知映射处理，界面显示当前条件；纸白／墨黑的绝对外观模拟可待专门标定。当前画布按 sRGB 显示，准确程度受纸张配置、屏幕校准及可显示色域限制。[高位深成片](../Sources/Imaging/ImagePipeline.swift) · [现有 Metal 画布](../Sources/UI/MetalPhotoView.swift)

**插件与宿主的分工。** 宿主提供 ICC 配置选择器，读取系统已安装或用户明确选择的输出配置，核验类型、大小与内容摘要，只传配置数据。插件用 ColorSync 建立“源色彩 → 所选印刷设备 → 带已知色彩空间的预览 RGB”变换，输出时标明预览色彩空间，绝不能只改像素标签。宿主将预览按其标签绘入现有画布，由 macOS 处理画布到当前显示器的转换。色域警告另按源色与目标配置做 gamut check，返回对齐到照片的覆盖图，宿主单独叠加；配置支持打样但无法检查色域时，只禁用警告并说明原因。损坏、缺失或不能建立双向打样变换的配置须报告，恢复普通画面。[Apple ColorSync 转换](https://developer.apple.com/documentation/colorsync/color-transforms) · [目标色域检查](https://developer.apple.com/documentation/colorsync/kcolorsynctransformgamutcheck)

**怎样验证。** 用带嵌入 ICC 的色卡、灰阶、饱和红与透明边，先以相同 sRGB TIFF16 在 Apple“预览”选择同一配置做实窗对照；只有印刷意图、黑点补偿与纸白策略一致时才作数值对照。用相同源／目标 ICC、意图和补偿设置直接调用 ColorSync 得到参考值，先比较未叠加警告的插件输出，再用已知色域内外的色块核对警告，切两份纸张配置、换照片、移动窗口到另一块显示器，检查标签、迟到结果和颜色管理。开启、关闭或中断插件后，核对配方修订及历史条数，并逐像素比较同一设置的正常导出；普通缩略图、直方图和编辑吸管均应保持原来的语义。另取一块普通显影中未发生高光剪切、但超出所选纸张色域的饱和色块，同时打开两种警告。该处只应出现色域标记；单独开关任一种警告，另一种的覆盖和鼠标 RGB 读数都应保持一致。真实纸样与校准显示器的比对留作印刷准确性验收。[画布取样与显示入口](../Sources/UI/PhotoCanvas.swift) · [ICC 与透明度回归基础](../Tests/AlphaTests.swift)

### 选取高光：验证插件能把编辑交还给 Phosdeck

用户点“选取高光”，即可预览一张亮部选区。宿主按当前旋转、透视和裁剪，从原生亮度范围基准生成裁区参考图。插件只统计最终裁区内有覆盖的像素，按原生范围工具的 Oklab 明度建议下限，返回一个原生亮度范围蒙版草稿。画布的临时缩放和平移不改变统计范围。确认后，用户可以拖动范围端点、用减选画笔排除一块反光，再用现有局部曝光控件压低高光。

**为什么选它。** Phosdeck 已有亮度范围、软边、画笔加减和局部调整。插件只补上“根据这张照片建议一个范围”，就能证明算法可以由第三方提供，而结果仍由工作区接手。宿主提供与原生范围工具一致的亮度尺度，让插件返回的数值和画面选中的区域对应起来。[亮度范围与蒙版组合](../Sources/Imaging/Masking.swift) · [现有取样与画笔交互](../Sources/App/MaskEditing.swift)

**怎样验证。** 用含明窗、室内亮斑与透明边的合成图，旋转后把最亮的窗完全裁掉。只改变裁区外窗户的亮度，再运行插件，两次建议的端点应一致，并与单独统计裁区内有效像素的参考值相符。比较插件草稿与应用后的原生覆盖，在一处室内亮斑上用画笔减选。应用只产生一次原生编辑，撤销能移除它。保存后停用插件并重开，范围端点、减选笔触和局部曝光都应能继续编辑。[范围取样、组合与几何回归](../Tests/MaskingTests.swift)

### 暖调印相：验证效果能留在显影流程中

用户在当前版本上拖动一个“强度”滑块，让照片逐渐呈现暖色印相效果。插件接收图像像素并返回着色结果。首批只开放一个固定位置：原生显影、局部调整、几何和暗角之后，输出缩放、颗粒和编码之前。用户之后改变曝光或裁剪，效果会对新的输入重新计算。

**为什么选它。** 新增一个单滑块、逐像素的效果，就能检验实时显影最重要的承诺：同一版本可反复调、预览与导出走同一个算法。它保留图像尺寸和透明度，强度为零时逐像素原样返回，便于定位偏色或重复处理。现有暗角与颗粒给出了明确的接入位置，主干 RAW 解码、白平衡和曝光继续由宿主管理。[原生显影顺序](../Sources/Imaging/ImagePipeline.swift) · [裁剪后暗角](../Sources/Imaging/CreativeVignette.swift) · [输出颗粒](../Sources/Imaging/FilmGrain.swift)

**怎样验证。** 连续拖动、切图再切回，松手后的画面应是最后一次取值。用含超白和半透明色块的合成图，对照同尺寸 1:1 预览、最终输出和强度为零的原生结果。用一张 6000 万像素的合成图依次保存两个强度，记录每次从确认到“已保存”的耗时、实际新增文件字节及峰值内存。单份未压缩 RGBA32F 阶段图约 960 MB，此数仅作预算参考。撤销回第一档，关库重开，对照先前保存的第一档输出；另在同一会话重做，核对第二档。再把第二档的曝光提高一档，保存并导出参考图，停用插件、关库重开，在相同设置下比较显示和导出像素。只改颗粒时核对沿用原阶段文件；模拟磁盘不足时，上一已存版本仍可重开，本次调整留在草稿。[预览调度回归](../Tests/ImagingTests.swift) · [图库归档](../Sources/Catalog/CatalogArchive.swift)

## 实现方案与平台依据

在 macOS 26 或更新版本，软打样、选取高光、暖调印相各用一份独立的 `.appex`，绑定同一个无界面的 `PhotoTool` 扩展点。系统负责发现和启动，扩展通过 **ExtensionFoundation + NSXPCConnection** 与 Phosdeck 通信。三个内置工具共用连接协议，各自在编辑工作区接入原生控件。开放第三方时，目标是由宿主读取工具描述来注册入口和生成通用控件，第三方可在自己的 Mac App 里分发相同格式的扩展。

| 调研依据 | 对 Phosdeck 的设计影响 |
|---|---|
| Apple 的扩展一次绑定一个扩展点，绑定包含宿主 bundle ID。扩展点默认仅限包内；macOS 可用 `Scope(restriction: .none)` 允许外部提供者。[定义扩展点](https://developer.apple.com/documentation/extensionfoundation/adding-support-for-app-extensions-to-your-app) · [扩展绑定](https://developer.apple.com/documentation/extensionfoundation/building-an-app-extension-to-support-a-host-app) | 一个扩展点内用工具描述区分三种结果。宿主生成扩展点定义，三个插件在各自的 `Info.plist` 声明绑定。正式版和固定体验版使用各自的宿主 ID，核对签名包中的扩展点和工作连接身份。 |
| Apple 的 Monitor 提供可用扩展身份和待批准、已停用数量；外部扩展默认需要用户批准。系统可以复用已有进程，断开一个连接后进程也可能继续存活。[发现与批准](https://developer.apple.com/documentation/extensionfoundation/discovering-app-extensions-from-your-app) · [进程管理](https://developer.apple.com/documentation/extensionfoundation/adding-support-for-app-extensions-to-your-app) | 系统批准与 Phosdeck 自己的启停偏好分别记录。系统进程、一次连接、一次编辑各有独立寿命。插件释放资源不能依赖下次一定启动新进程。 |
| Apple 支持通过 Foundation XPC 传递 `FileHandle`，也提供连接和匿名监听器的对端签名约束。FxPlug 4 证明另一种选择是跨进程共享 IOSurface。[Apple DTS 的句柄说明](https://developer.apple.com/forums/thread/785735) · [连接签名校验](https://developer.apple.com/documentation/foundation/nsxpcconnection/setcodesigningrequirement%28_%3A%29) · [监听器签名校验](https://developer.apple.com/documentation/foundation/nsxpclistener/setconnectioncodesigningrequirement%28_%3A%29) · [FxPlug 跨进程渲染](https://developer.apple.com/documentation/professional-video-applications/using-out-of-process-fxplug-plug-ins) | 首版选普通沙箱中的 NSXPC，利用只读句柄移交完整图像，先取得可以逐像素比对的基准。系统连接只交换工作端点，像素经独立的已核验连接传递。GPU 共享的设备、同步与复用约定等实测表明需要时再加。 |
| OpenFX 分开描述能力、创建实例、渲染和销毁实例。[OpenFX 动作定义](https://openfx.readthedocs.io/en/latest/Reference/ofxImageEffectActions.html) | 借用这个生命周期划分。Phosdeck 的实例绑定一张照片的一次操作；照片版本、原生草稿和图库提交由宿主定义。 |

### 开发者实现什么

新增一个不依赖 App、GRDB 或 SwiftUI 的 Swift 模块 `PhosdeckPluginKit`，由宿主和扩展共同使用。它包含工具与图像描述、有限的结果类型、XPC 消息编解码和扩展端接线。三个扩展都只依赖这个模块及各自的算法。宿主内部在 App 层管理发现、连接和调用，在 Imaging 层准备像素、接回结果，在 Catalog 层只登记用户确认的编辑。观片预览使用窗口本地的临时状态。Xcode 工程与 `project.yml` 同步登记 SDK、扩展目标和嵌入关系。[现有目标与签名配置](../project.yml)

每份扩展提供一个工具。握手交换接口版本、稳定的工具键、显示名、接入口和算法版本，像素阶段与参数类型由首批三个工具的协议约定。配置附有摘要和受限的只读数据，插件无须浏览用户目录。通用入口上线时，工具描述还需提供输入阶段及各参数的稳定键、类型、默认值和范围，供宿主校验参数和生成控件。上线一个新算法版本时显式改变算法版本号；改显示名不影响已存照片。

首批 SDK 以预览版提供，覆盖三个内置工具实际使用的接口。开发者实现一个异步处理函数。下面用暖调说明调用边界，类型名供实现时对照。

```swift
protocol PhotoTool: Sendable {
    var descriptor: ToolDescriptor { get }
    func evaluate(_ request: ToolRequest, input: PluginImage, profile: Data?) async throws -> ToolResult
}
```

`request` 给出参数与用途（草稿预览、质量预览或最终处理），`PluginImage` 提供当前尺寸和像素。返回值只能是工具声明的那一类：观片预览（同尺寸、按协议编码的图像和可选的色域警告覆盖图）、原生编辑建议，或同尺寸的显影阶段图像。观片预览只能交给窗口显示。首版原生编辑建议只需表达“新增一个亮度范围蒙版”，包括上下限与软边。宿主检查取值并创建原生对象和标识。SDK 将取消转成 Swift 任务取消，插件在耗时循环中检查它。三个工具都可以写成无状态算法；会话表、消息标识和关闭连接由 SDK 管理。

### 从发现到关闭

1. **发现。** 宿主启动时建立 `AppExtensionPoint.Monitor` 并观察变化。首版通过“设置 → 插件”的系统扩展管理界面启停随包扩展。宿主每次派发前检查可用列表，握手时拒绝不兼容的接口。开放第三方后，可为可用且已启用的新扩展建立短连接读取工具描述，移除或更新时使展示缓存失效。
2. **连接与握手。** 宿主持有 `AppExtensionProcess`，通过 `makeXPCConnection()` 取得发布者声明和匿名监听端点。此系统连接只支持这一个控制请求。在 macOS 26.6.2 的探针里，扩展对系统交入的连接直接设置签名要求会崩溃。工作连接使用匿名 `NSXPCListener`。扩展在开始监听前约束宿主 Team ID、签名标识和 Apple 签名链，宿主在连接激活前约束预期发布者、系统发现的扩展 bundle ID 和 Apple 签名链。双方设置允许的消息类型和失联回调。工作连接先交换不含照片数据的 `describe`，复核发布者、工具描述和主版本，成功后才交付像素。持久身份绑定已核验的 Team ID、扩展 bundle ID 和工具键，重开另外匹配算法版本。首批内置插件均核验宿主所属团队。换发布者的同名工具按新工具处理。
3. **打开操作。** 用户打开工具，或后台导出遇到已保存的效果时，宿主冻结图库会话、照片版本、来源摘要、配方修订和输入阶段，生成会话 ID。插件只看到不透明的会话 ID 与执行所需的描述。宿主按需连接，连接结束后仍能从冻结数据重建任务。
4. **试调与确认。** 拖动参数产生新的草稿修订。每个计算请求携带会话 ID、请求 ID、修订、用途、完整参数和输入。输入内容、比例或质量改变就提供新的输入描述。观片会话在换照片时关闭并绑定新版本，编辑照片时用新修订刷新；配置或意图改变时只替换预览请求。关闭打样即结束，不进入提交。用户确认可保存的编辑后，宿主请求最终结果并复核来源、配方和参数，再进入提交。只有已核验的工具身份、最终输入、算法版本、参数、尺寸和质量全部匹配时才复用结果。
5. **结束。** 每次计算结束时，宿主关闭工作会话。停止观片、取消编辑或关闭图库时，宿主作废在途预览并通知扩展取消。SDK 关闭本会话句柄。正常结束的连接可在一秒空闲期内为下一次滑块更新复用，期满使连接和进程引用失效。连接中断会使其所有会话失效，恢复时重新握手并创建新会话。历史和已保存文件可独立于扩展进程使用。

### 跨进程的调用协议

所有请求从宿主发出，异步返回一次成功或失败。XPC 接口只接受白名单里的控制字段和文件句柄。控制消息使用固定结构，限制字符串长度和项目数量，每种接入口有独立的结果校验。连接中断、超时和迟到回复由同一处结束请求，一次请求只通知一次结果。

| 消息 | 谁在什么时候调用 | 双方约定 |
|---|---|---|
| `describe` | 宿主发现插件或建立新连接 | 返回工具描述与兼容版本，完成握手后才接受工作消息。 |
| `open(session, tool)` | 一次试调或后台渲染开始 | 确立此次操作；重复发送相同的打开请求可返回原确认，同 ID 而描述不符则报错。 |
| `evaluate(session, request, revision, purpose, parameters, input)` | 参数改变、质量预览或生成最终结果 | 返回同一请求标识及类型化结果。已关闭会话、未知工具、错误输入类型直接拒绝。计算不写图库，进度可由宿主先显示为“处理中”。 |
| `cancel(session, request)` | 请求被替换、用户取消或超过宿主时限 | 宿主即刻作废结果并通知 SDK。工作队列可在计算期间收到取消通知，等该次计算释放资源后由原 `evaluate` 应答。重复取消可安全忽略。 |
| `close(session)` | 本次操作结束 | 可重复调用。失联时两端各自清理所持资源，宿主按回收状态结算额度。 |

编辑工具提供“预览”和“应用”，观片工具提供“开启”和“关闭”。对插件而言，它们都是对一个冻结输入求结果。**提交是宿主自己的动作。** 例如选取高光只会返回亮度范围；即使扩展重复回复，只有用户确认的那次宿主事务可以建立蒙版和历史。协议错误区分不兼容、输入或结果无效、超出资源预算、取消、超时、进程失联、保存冲突；按错误给出重试、重开草稿或查看已存版本的入口。

**以暖调滑块为例。** 宿主打开会话 S，发出第 1 次草稿请求，强度 20%。用户拖到 60% 时，宿主只保留最新待算参数。松手并确认后，最终请求使用 60% 和全尺寸输入。即使先前的 20% 预览在此时才返回，也不能覆盖最终画面或登记历史。全尺寸结果核验完成后，宿主在图库事务里再次比较照片版本，成功才登记一次历史并关闭 S。下次导出可以新建会话，也可以读取匹配的已存阶段结果。

| 事件 | 宿主的状态变化 | 恢复方式 |
|---|---|---|
| 调整参数或预览失败 | 保留草稿和出错原因；超时立即作废该请求，观片工具恢复普通画布 | 重试前检查该插件所有会话共用的额度，必要时断开连接清理 |
| 关闭观片或打样失联 | 立即移除窗口的预览与警告叠加，作废在途请求 | 恢复普通画布，重新开启后用当前照片和配置建会话 |
| 用户确认编辑，或切图、导出前需要保存草稿 | 冻结草稿与宿主操作 ID，异步准备固化件。合并针对同一草稿的保存请求 | 保存成功后继续有效的原操作。失败时保留草稿，版本冲突时按新版本重新预览 |
| 发布前取消、图库会话失效或插件失联 | 作废在途结果，取消等待中的操作。图库会话仍有效时保留草稿 | 重试计算时创建新会话和请求 ID。恢复已有收据的保存使用原操作 ID |
| 固化件已发布或图库事务已提交 | 根据发布前持久化的收据核验文件并续接登记。已提交的操作返回既有结果 | 重启后按同一操作 ID 恢复。仅在当前会话的事务成功后登记原生撤销 |

### 图像通过什么交付

图像描述包含阶段、全尺寸与实际像素尺寸、行跨度、像素格式、颜色空间、alpha、行方向和字节数。首版工作像素使用扩展线性 sRGB、RGBA32F、小端、直通 alpha 和自上而下的行。宿主从 Core Image 读回预乘浮点像素，再转成直通 RGB 和 alpha，将有限覆盖率约束在 0～1，完全透明的像素归零。软打样输入由宿主把送印源的 sRGB 编码值转换成协议的线性 RGBA32F，附描述这些实际字节的扩展线性 sRGB 配置。打印机与纸张的目标 ICC 单独传递。插件以实际输入配置为起点做印刷模拟，并给返回像素附上与其编码一致的 RGB 配置；宿主按该配置完成最终显示转换。高光取得与原生亮度范围工具一致的有向参考图，暖调取得暗角之后的阶段图。三个工具均无需原片路径、图库书签或数据库。[现有浮点读写](../Sources/Imaging/MultiFrameImage.swift) · [蒙版基准](../Sources/Imaging/ImagePipeline.swift)

内置和第三方扩展统一通过任务私有普通文件的只读 `FileHandle` 交接图像、色域覆盖图和自定义 ICC 数据。XPC 为这些载荷传递描述和句柄。生产方写完并关闭写端后移交读端。宿主在读取前检查声明的尺寸、行跨度、乘法溢出、文件类型和实际长度，并在复制时执行已预留的字节上限。结果有界复制到宿主独占的暂存区，再核验副本的有限像素、透明度、尺寸和摘要，供显示或保存。双方各关闭所持句柄，恢复时只清理可确认归属且无活跃引用的暂存。

**跨会话限额。** 宿主按插件身份，对预览、导出和重试共用在途任务数与字节预算。派发前预留额度，达到任一上限就暂停派发。超时或取消立即结束宿主等待，观片工具恢复普通画布。宿主继续保留已发请求的额度，关掉迟到回复携带的句柄后丢弃结果。连接中断仍可能留下正在运行的扩展。所有窗口共用原预算，确认旧任务应答且句柄已释放，或系统确认进程退出且宿主完成清理后，归还该任务的额度，每笔只归还一次。超时或失联后的下一次调用重新握手。[Apple 扩展进程管理](https://developer.apple.com/documentation/extensionfoundation/adding-support-for-app-extensions-to-your-app) · [进程退出通知](https://developer.apple.com/documentation/extensionfoundation/appextensionprocess/configuration/oninterruption)

### 三种结果怎样接回现有代码

| 工具 | 调用与接回位置 | 关闭、保存或重开 |
|---|---|---|
| 软打样 | 取成片显影与颗粒之后、画布 8 位量化之前的高位深输入，按上述 sRGB 送印条件准备像素。插件输出仅接到 `PhotoCanvas` 的照片显示层，画布背景与编辑覆盖由宿主绘制。 | 缓存仅限窗口，键含已核验工具身份、算法版本、照片版本、显影修订、源色彩空间、尺寸、目标 ICC 摘要、意图和警告开关。接收时再核对窗口与会话；显示配置变化时刷新画布。画布分别接收打样照片、同一修订的普通显影图和插件的色域覆盖图。打样照片供观看；鼠标读数和高光剪切取普通图；色域标记只取覆盖图。三路使用相同的画布坐标。普通缩略图、直方图、各编辑吸管和导出沿用各自原有输入。[画布](../Sources/UI/PhotoCanvas.swift) · [预览发布](../Sources/App/AppModel.swift) |
| 选取高光 | 用 `maskReference` 的基准与 [PhotoGeometry](../Sources/Imaging/PhotoGeometry.swift) 的当前几何准备裁区参考图；范围统计沿用[原生明度定义](../Sources/Imaging/DevelopKernels.metal)。插件只返回上下限与软边，宿主在原生源平面计算覆盖，按当前几何显示。 | 确认时把建议合入冻结草稿，以预期照片版本执行配方事务，再登记一次撤销。冲突保留草稿并提示重新预览。保存后，重开、修边、撤销和导出都走现有原生路径。[亮度范围](../Sources/Imaging/Masking.swift) · [带版本检查的保存](../Sources/Catalog/CatalogStore.swift) |
| 暖调印相 | `ImagePipeline` 的普通出图和交互出图均在 `graph` 的完整显影结果与 `resized/finish` 之间调用同一个异步阶段。短路返回的蒙版、点颜色等内部取样维持各自阶段。缩略图、1:1 检查和导出共用该阶段；首版 1:1 从完成图裁块。 | 首次应用暖调、改变暖调强度，以及后续通过任何编辑入口保存曝光或裁剪等上游变化，都走同一保存流程。拖动期间只更新草稿；确认时准备与新输入匹配的全尺寸阶段结果。只改下游颗粒时沿用原固化件。把参考键纳入预览缓存，并把含插件效果的配方排除于“未编辑原图”快捷路径。[预览、导出与取样](../Sources/Imaging/ImagePipeline.swift) · [配方类型](../Sources/Imaging/EditRecipe.swift) |

现有 `ImagePipeline` 是 actor，核心建图和多数渲染方法是同步的。实施时在上述阶段拆出“准备输入”和“接回结果”，保留无插件照片的原有渲染路径。处理插件效果的调用链允许异步等待；在等待 XPC 前冻结自包含的像素和版本，返回时再验证。不得把可变 RAW 滤镜、渲染器缓存或正在写的缓冲区跨等待交给另一个任务。App 主线程只接收进度、结果及错误。整帧文件探针下，拖动从长边 960 px 草稿开始，参数变化未影响上游阶段时复用同一份只读输入，停手后请求质量预览。拖动沿用现有合并逻辑，每个交互会话至多一个运行中的草稿和一个最新待处理草稿；质量或导出有独立的有界预算，慢调用不能无限阻塞后续工作。旧照片、已作废请求和过期质量结果一律丢弃。[预览调度与发布](../Sources/App/AppModel.swift) · [连续输入回归](../Tests/ImagingTests.swift)

### 实时效果的保存与恢复

现有切图、打开导出和切库等操作依赖同步的 `commitRecipe()`。草稿需要新固化件时，这些入口与“应用”共用异步提交。在后台准备和核验全尺寸阶段结果期间，宿主冻结图库会话、目标照片、草稿及预期修订，记录发起保存的操作，并在界面显示正在保存。计算与写盘在主线程和图库事务之外进行。保存成功后，宿主复核原操作仍然有效，再继续切图、打开导出或切库。失败或发布前取消时保留草稿和上一已存版本，结束等待中的操作。[原生切图、导出与保存入口](../Sources/App/AppModel.swift)

原生批量编辑和 MCP 批量提交复用相同的准备、核验与提交步骤。逐张准备需要的新固化件，全部就绪后以一次图库事务提交整批，登记一次原生撤销。任一目标准备失败或修订冲突时，整批的已存配方和历史保留原样。[批量提交契约](agent-integration.md#逐张调整并批量提交)

宿主维护固化件与当前配方、历史、快照、虚拟副本和冻结导出的引用。预览和固化件的复用键均包含已核验的签名发布者（Team ID）、扩展 bundle ID 和工具键，再结合来源摘要、实际生效的上游配方与解码版本、阶段和几何、算法版本、参数、尺寸及像素契约。恢复已存版本要求完整质量的结果。

固化件先暂存并核验。**发布前持久化收据**，记录宿主操作 ID、图库和照片 ID、冻结配方与预期修订、暂存文件身份、目标位置和核验摘要。无覆盖发布并回读后，在同一图库事务中复核预期版本、登记配方、阶段文件引用和带操作 ID 的历史。事务成功后才删除收据、显示“已保存”并登记撤销。重启后，先用历史中的操作 ID 判定事务是否已完成。尚未完成时，依收据核验已发布文件的身份与摘要，再以同一操作 ID 续接。版本冲突或文件不符时报告原因，保留上一已存版本。恢复时按收据确认暂存文件归属。[收据与发布实现](../Sources/Catalog/PluginStageCommit.swift)

撤销和重做切换引用。整库归档按数据库快照收集当前配方、历史、快照及冻结导出引用，把阶段文件一起复制。打开归档时核验文件摘要并恢复到本机。数据库单独备份恢复时标明缺件。缺插件且已有匹配固化件时，从该阶段继续计算。上游已改、空间不足或校验失败时保留新草稿与上一已存版本，新版本的最终导出需等待插件或有效固化件。[整库归档](../Sources/Catalog/CatalogArchive.swift) · [数据库备份与历史](../Sources/Catalog/CatalogStore.swift)

### 实施顺序与验证

1. **先证明独立安装和调用。** 在 macOS 26 的签名宿主上，让同一工具分别以随包扩展、另一团队独立公证的容器 App 安装。记录系统批准、工具描述、工作连接的签名核验及像素往返。核对正式版与体验版各自的绑定，试停用、重新启用、握手失败、主动中断和超时。开发签名的本地成功仅覆盖开发环境。[Developer ID 公证](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)

   [探针工程](../scripts/plugin-probe/project.yml) 独立于正式 App。用 [构建脚本](../scripts/plugin-probe/build.sh) 指定宿主签名身份、宿主 Team ID 和独立容器签名身份。先打开产物 `ProbeVendor.app` 注册容器，再以 `--manage` 打开 `ProbeHost.app` 的系统扩展开关。宿主可执行文件支持 `--snapshot` 获取发现状态，默认核对随包扩展的签名、像素与故障恢复，`--vendor` 切换到独立容器，`--inline` 验证不符合图像消息类型的返回。用 `--measure` 复测 960 px 与 2400 px 预览及连续拖动，用 `--final` 复测 6000 万像素的阶段文件写入与校验。逐次结果输出为 JSON Lines，可保存在 `build/`。合成阶段探针计时到 MainActor 发布，成品验收还需要实际显影管线和实窗测量。

   用 [固定体验版更新脚本](../scripts/update-preview.sh) 更新已有开发签名的体验包。脚本在同卷暂存构建产物，用 [体验版绑定脚本](../scripts/bind-preview-photo-tools.py) 同步宿主、扩展点、扩展 bundle ID 和工作连接所用的宿主 ID，再沿用原开发身份从扩展到宿主签名并核验。`PluginSystemTests` 核对正式构建中的绑定、签名工作连接、像素行序、源平面高光选区、保存衔接和阶段文件恢复。

   - 分别模拟超时后迟到回复和计算始终不结束。跨窗口、新会话和重连反复请求时，核对未回收额度继续占用、无法确认回收的插件停止接单、迟到结果被拒收，其他照片仍可正常编辑。确认旧任务收尾或进程退出后，验证额度只归还一次且可以恢复派发。
   - 用测试扩展返回违反协议的内联图像数据，再返回实际长度超过预算的文件句柄。核对宿主拒收内联像素和超预算文件，后者在开始复制前即报告失败，并记录宿主内存峰值及正常编辑是否可继续。

2. **依次接上三个真实工具。** 软打样验证 ICC 资源、画布隔离与色域警告，选取高光验证原生草稿与撤销，暖调验证带插件的实时预览、历史、归档与导出。每项都从工作区普通入口走完前述用例；用相同输入核对直接执行算法、随包扩展和独立扩展的结果。

   - 保存暖调后拖动曝光，立即切图或打开导出，核对动作只在成功保存后继续一次。Agent 批量修改两张照片时，让其中一张固化失败，核对两张照片的已存配方与历史。
   - 让两个已通过握手的扩展使用相同工具键、算法版本和参数，输出不同像素，核对预览缓存和固化件按已核验的工具身份区分。在固化件发布后、图库事务前中断，重开后依收据核验并续接一次，确认重试沿用同一文件和历史记录。

3. **用最慢的一条决定优化。** 在同一公开或合成样片上分开记录准备像素、跨进程交付、计算、回读、主线程发布及固化写盘时间，并测峰值内存。对换图、连续拖动、磁盘不足、插件升级与无插件重开做故障验证。实测数据与用户体验共同决定可接受的时限、字节预算和是否推进分块或 IOSurface。
